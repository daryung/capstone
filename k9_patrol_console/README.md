# Go2 오디오 파일 재생

메인 상단 **오디오 재생** → 파일 선택 → **로봇에 전송** → 목록 선택 → **재생**.
Go2 연결 후 사용하며, **일시정지**로 재생을 멈춥니다. 업로드만으로 자동 재생하지 않습니다.
WAV / MP3, 최대 30초·8MB. MP3 또는 WAV 변환에는 ffmpeg가 필요합니다.
녹음 중에는 재생이 차단됩니다. 재생 승인 메시지는 로봇의 요청 수락을 의미하므로 실제 소리는 현장에서 확인하세요.
기존 data 폴더를 유지하면 저장 기록이 유지됩니다.

# 메인 화면 간소화

메인: 영상 → 수동 메모·녹음 → 중요 기록·장면과 LLM 선정 이유. 상단 설정에서 연결·조종·수동 관찰·탐지·모델 설정을 엽니다. 설정은 모달 창이며 닫으면 메인으로 돌아옵니다.
중요 기록 선정은 기본적으로 전체 저장 기록 중 완료·일부 저장된 자료를 검토합니다. 설정에서 현재 순찰만 선택할 수 있습니다.

# K9 PATROL — 사각지대 순찰 UI

고정 CCTV 사각지대 순찰을 위한 사족보행로봇의 이상 자세 감지 및 원격 상태 확인 시스템에 맞춰 관제 UI를 재구성했습니다.
첨부 코드를 기반으로 UI를 단순화하고, Go2 WebRTC AudioHub 오디오 파일 전송·재생·일시정지를 연결한 버전입니다. 자동 포즈 및 음성 응답 판정은 미구현입니다.

## 실행

기존 서버를 Ctrl+C로 종료하세요. 이 폴더를 기존 k9_console 옆에 풀고 기존 가상환경을 활성화한 터미널에서:

```bash
cd k9_patrol_console
python -m pip install -r requirements.txt
python app.py
```

브라우저: http://127.0.0.1:8000 (localhost 대신 정확히 이 주소 사용)
다른 폴더에서 실행할 경우 포함된 모델이 로드되도록 이 폴더로 먼저 이동하세요.
기존에 동작하던 unitree_webrtc_connect 설치와 GO2_AES_KEY 환경변수를 그대로 사용합니다. 키를 코드에 넣지 마세요.
기존 설치에서 수정한 robot/connection.py가 있다면 그 파일을 계속 사용할 수 있습니다.
다른 서버가 8000 포트를 사용하면 `python app.py --port 8001`로 실행하세요.

## 화면과 실제 동작

- 순찰 관제: 기존 WebRTC RGB 영상, 사람 탐지, 누르는 동안 원격 이동·자세 명령.
- 상태 확인: 사용자가 구역·자세·움직임·직접 들은 응답·후속 상태를 입력.
- 수동 관찰 타이머: 영상 수신 중 사용자가 시작. 15초 경과만 표시하며 자동 자세 판정·방송·LLM 호출은 하지 않음. 타이머는 사용자 수동 관찰 시간으로 기록.
- 관찰 내용·현재 장면 저장: 위 입력을 시각과 함께 메모에 저장하고 원본 이미지 및 전후 영상을 기존 DB에 저장.
- 사건 기록: 원본 검토, 메모 편집, 제외 설정, 키워드 검색, JSON 내보내기.
- 맥락 해석: 검색된 완료 기록을 로컬 Ollama에 전달. 확인된 단서·불확실성·추가 확인 제안을 한국어로 생성. 원본 기록 참조 제공.
- 영상 연결 전에는 캡처·저장 불가. 수동 관찰 타이머도 시작 불가.

## 아직 미연결인 기능 (UI에 명시)

- yolo11n.pt는 객체 탐지 모델이며 포즈 모델이 아닙니다. 자동 저자세 감지, 동일인 추적, 15초 지속 판정은 미구현.
- RealSense RGB-D는 미연결. 현재 화면은 Go2 전방 RGB 영상입니다.
- 마이크 녹음, STT, 무응답/움직임 자동 판정은 미구현. 스피커 파일 재생은 아래 절차로 사용 가능합니다.
- LLM은 영상·음성 원본을 직접 입력받지 않습니다. 관측 시각·STT 발화 원문·사람 등장·규칙 기반 자세 후보를 읽어 기존 저장 기록을 고릅니다.
- 이 버전은 이벤트 발생 시 자동 LLM 호출하지 않고 사용자 버튼으로 실행합니다.
- 실제 게임패드 입력은 미구현. 기존 화면 버튼 또는 Shift+WASD/QE로 조종합니다.
- 배터리·위치·실측 지연 등 미수신 값을 생성하지 않습니다. 구역은 사용자 입력이며 로봇 좌표가 아닙니다.

## Ollama

기본 모델 qwen3.5:4b. 모델명을 화면에서 변경할 수 있습니다.
기본 URL http://127.0.0.1:11434 이며 `K9_OLLAMA_URL`로 변경합니다.
Ollama가 Windows, 서버가 WSL이라면 기존 네트워크 연결 설정을 먼저 해결해야 합니다. 이번 UI 변경이 그 연결 문제를 해결하지는 않습니다.
LLM이 쓴 내용은 원본과 비교해 사용자 검토가 필요합니다. 건강 상태·의식·생존 여부를 확정하지 않습니다.

## 기존 데이터 유지

기존 k9_console/data를 삭제하지 마세요. 기존 자료를 사용하려면 아래처럼 지정할 수 있습니다.

```bash
python app.py --data ../k9_console/data
```

같은 DB를 두 서버에서 동시에 수정하지 마세요. 선정 결과 다운로드는 선택 이유·근거·원본 파일 참조를 담은 JSON입니다. 원본 미디어 자체를 포함하지 않습니다.

## 저장과 보안

이미지·영상은 data/media, 관찰 메모·선정 이력은 data/records.sqlite3에 저장됩니다.
전후 영상은 기본 전 3초·후 3초. ffmpeg가 있으면 MP4 변환, 없으면 AVI 다운로드.
사람 탐지 이벤트는 클래스 등장 기준으로 개별 사람의 신규 등장 판정이 아닙니다.
이동 키·버튼 해제 또는 화면 이탈 시 정지 요청하며 실제 정지는 현장과 리모컨으로 확인하세요.

## 검증 범위

Python/JS 문법, 로컬 HTTP, DOM 이벤트를 통한 화면 전환·미연결 가드·수동 기록 저장 흐름을 확인했습니다.
브라우저 실행 파일을 확보하지 못해 실제 렌더링과 화면 크기별 시각 검증은 완료하지 못했습니다.
실제 Go2 연결·이동, 실제 YOLO 추론, 실제 Ollama 생성은 사용자 장비에서 추가 확인이 필요합니다.


## 안내 음성 재생 (추가)

1. 기존처럼 Go2에 연결합니다.
2. 상태 확인 패널의 ‘안내 음성’에서 WAV 또는 MP3 파일을 선택합니다.
3. ‘로봇에 전송’을 누릅니다. 로봇 저장 목록에서 등록을 확인할 때까지 진행 상태가 표시됩니다.
4. 목록에서 파일을 선택하고 ‘재생’을 누릅니다. 반복 없는 no_cycle 모드로 재생 요청합니다.
5. 중단하려면 ‘일시정지’를 누릅니다. 연결 해제는 로봇에서 재생 중인 음성의 정지를 보장하지 않으므로 필요하면 먼저 일시정지하세요.

이미 로봇에 저장된 음성은 ‘목록 조회’로 가져올 수 있습니다. PC 스피커가 아니라 Go2 스피커로 요청합니다.
재생 요청 승인은 실제 소리 출력이나 방송 종료 확인이 아닙니다. 로봇 볼륨은 기존 앱/설정에서 조절하고 현장에서 확인하세요.
첫 안내 문구를 자동 생성하지 않으므로 ‘괜찮으신가요? 도움이 필요하시면 말씀해 주세요’ 녹음 파일을 직접 선택하세요. TTS는 추가하지 않았습니다.

- 최대 8MB, 최대 30초. 파일은 data/audio에도 보관됩니다.
- 44.1kHz, 16bit PCM, mono/stereo WAV는 ffmpeg 없이 사용 가능합니다.
- MP3 또는 다른 WAV 형식은 ffmpeg로 44.1kHz mono PCM WAV 변환합니다. 설치:

```bash
sudo apt update
sudo apt install ffmpeg
```

- WebRTC 업로드는 작은 블록 단위라 파일 길이에 따라 시간이 걸릴 수 있습니다. 전송 중에는 다른 오디오 요청을 차단합니다. 조종 명령은 별도 루프에서 계속됩니다.
- HTTP 요청은 작업을 시작하고 상태 폴링으로 결과를 표시합니다. 로봇 RPC의 오류 코드를 검사하며 오류를 성공으로 표시하지 않습니다.
- 현재 드라이버에 AUDIO_API가 없으면 명확한 오류를 표시합니다. 기존 연결이 정상인 드라이버를 무조건 업데이트하지 말고 먼저 오류를 확인하세요.

### 구현 참고

https://github.com/legion1581/unitree_webrtc_connect/blob/master/unitree_webrtc_connect/webrtc_audiohub.py

동일한 rt/api/audiohub/request 토픽과 AUDIO_API 상수를 사용합니다. GET_AUDIO_LIST, UPLOAD_AUDIO_FILE, SET_PLAY_MODE, SELECT_START_PLAY, PAUSE를 연결했습니다.
업로드 후 목록을 새로 조회하여 CUSTOM_NAME과 UNIQUE_ID를 확인합니다.

### 추가 검증

가짜 로봇 RPC를 사용한 단위 검증으로 청크 전송, 목록 재조회, 단일 재생·일시정지 요청, 요청 거부 및 미연결 오류 처리를 확인했습니다.
실제 Go2 스피커 출력·펌웨어 호환성은 사용자 장비에서 확인해야 합니다.


## 수동 녹음 및 STT

```bash
python -m pip install -r requirements.txt
python app.py
```

- 관제 화면의 기록 영역에서 **녹음 시작**을 누르면 로봇 마이크를 수신합니다.
- 같은 버튼의 **녹음 종료·저장**을 누르면 원본 WAV를 저장한 뒤 STT로 변환합니다.
- 자동/주기적 녹음, 키워드에 따른 저장 필터는 없습니다. 기존 설정 파일의 enabled 값도 무시합니다.
- STT는 한국어 faster-whisper Small / CPU INT8(2스레드) 기본이며 음성 메뉴에서 변경합니다.
- STT 모델 최초 사용 시 인터넷 다운로드가 필요합니다. Windows Ollama와는 별개입니다.
- 원본 WAV를 먼저 저장하므로 STT 다운로드·변환이 실패해도 기록에서 원본을 재생할 수 있습니다.
- 변환 결과는 TXT·시간대별 JSON과 DB에 저장하며 기록 탭에서 검색·재생·메모 검토·중요 기록 선정에 사용할 수 있습니다.
- 무음 또는 인식 문장이 없어도 수신된 원본은 저장합니다. STT 결과는 원본으로 검토하세요.
- 녹음은 최대 10분이며 최대 시간 또는 10초간 수신 중단 시 자동 종료·저장합니다. 반복 녹음은 시작하지 않습니다.
- 연결 해제 시 수신한 부분을 종료·저장하며, 재연결해도 버튼을 다시 누르기 전에는 녹음하지 않습니다.
- 프로그램을 정상 종료하면 수신 부분의 저장을 최대 5초 기다립니다. 강제 종료 시 아직 메모리에 있는 녹음은 손실될 수 있습니다.
- 녹음 중에는 안내 음성 재생을 차단합니다. 원본에는 현장의 다른 소리가 포함될 수 있습니다.
- 원본: data/media/<기록ID>.wav / 변환 결과: 같은 이름의 .txt, .json / DB: data/records.sqlite3.
- 시각은 PC 수신 기준이며 문장별 구간은 WAV 시작 기준입니다. 로봇 위치와 발화자는 자동 확정하지 않습니다.
- 자세 분류 및 기존 영상 기능은 그대로 유지됩니다.

## 규칙 기반 자세 후보 표시

`posture_rules.py`에서 COCO 17개 관절과 사람 박스를 사용합니다. 기본 관절 신뢰도 기준은 0.45입니다.

- 서 있음 후보: 몸통 수직 편차 30도 이하, 무릎 각도 155도 이상, 골반 각도 150도 이상, 발목이 골반 아래.
- 앉아 있음 후보: 몸통 수직 편차 40도 이하, 무릎 55~140도, 골반 45~140도, 허벅지 수평 편차 35도 이하.
- 누워 있음 후보: 몸통 수직 편차 65도 이상, 사람 박스 및 유효 몸통·하체 관절의 가로/세로 비율 1.25 이상.
- 양쪽 어깨·골반과 최소 한쪽 하체가 필요합니다. 완전히 보이는 양쪽 다리의 조건이 상충하면 서 있음/앉아 있음으로 분류하지 않습니다.
- 낮은 신뢰도, 가림, 작은 몸통, 애매한 굽힘은 판단 불가로 표시합니다.

영상 위에 번호와 자세 후보, 영상 아래에 한국어 상태를 표시합니다. 번호는 현재 프레임 순서이며 개인 식별/추적 ID가 아닙니다.
원본 영상은 그대로 저장하고, 촬영 당시 탐지 메타데이터에 관절·규칙 결과·측정 각도를 저장합니다.
기록에서 자세 후보를 볼 수 있고 자세 이름으로 검색할 수 있으며 LLM 선정에도 후보로만 전달합니다.
Windows의 맑은 고딕을 찾으면 영상 라벨도 한국어로 표시합니다. 다른 환경은 K9_KOREAN_FONT로 폰트 경로를 지정하거나 영어 영상 라벨을 사용하며, 화면 아래 상태는 항상 한국어입니다.

2D 규칙은 정면의 앉은 자세, 쪼그림, 숙임, 카메라 기울기, 원근 변화에 취약합니다. 기준은 고정/수평 카메라와 충분히 보이는 사람을 전제로 한 초기값이며 실환경에서 조정해야 합니다.
시간 누적, 인물 추적, 낙상/의식 판단은 포함하지 않습니다. 자세 이름은 의료적 상태가 아닌 관찰 후보입니다.
검증: 합성 관절의 세 자세 및 가림/퇴화/상충 사례, 영상 처리 연결, UI 표시와 기록·선정 근거 전달. 실제 영상 분류 정확도는 별도 검증해야 합니다.


## 중요 기록·장면 선정

기존 LLM 요약 입력창 대신 선정 카드가 표시됩니다.

1. 영상·음성·메모를 저장합니다.
2. 관제 화면의 **중요 기록·장면 → 선정**을 누릅니다.
3. LLM이 우선 검토할 저장 기록을 최대 5개 고르고 각각 선택 이유를 작성합니다.
4. 카드에서 원본 이미지, 저장 영상/음성 재생, 시각, 선정 근거를 확인하거나 원본 기록으로 이동합니다.

설정: 전체 저장 기록 / 현재 순찰, 최대 3·5·8개. 선정에서 제외한 기록과 처리 중·오류 기록은 입력에서 뺍니다.
중요 근거가 없으면 빈 결과를 허용합니다. 서 있음·누워 있음 후보와 STT 발화만으로 위험을 확정하지 않습니다.
현재 텍스트 LLM은 원본 영상/음성을 직접 분석하지 않으며 기존 클립 내부에서 새로운 구간을 찾아 자르지도 않습니다.
관측 시각·음성 인식 원문·사람 등장·자세 후보로 기존 저장 기록을 선택합니다.

기록 10개씩 검토하고 후보를 다시 비교합니다. 기록 수가 늘면 호출 횟수·처리 시간도 늘며 묶음별 선정은 전체 최적 순위를 보장하지 않습니다.
로컬 모델 문맥을 제한하기 위해 긴 기록은 텍스트를 발췌합니다. 발췌한 기록 수와 해당 근거의 발췌 여부를 화면에 표시하므로 원문 전체 검토로 해석하지 마세요.
생성 결과의 원본 record_id와 evidence_ids, 중복·최대 개수·문자열 형식을 서버에서 확인합니다. 이는 참조 검증이며 선택 이유의 사실 정확성을 보장하지 않습니다.
처리 중 수정·제외된 선택 기록은 결과에서 빼고 다시 선정하도록 안내합니다.
LLM 이력은 DB의 새 highlights 테이블에 저장합니다. 기존 records·summaries 테이블과 원본 파일은 유지합니다.
이전 선정은 생성 시점의 스냅샷입니다. 원본 메모를 고쳤으면 다시 선정하세요.

API: POST /api/highlights, GET /api/highlights/history, GET /api/status의 llm 필드.
수동 녹음·STT와 자세 후보 표시 등 기존 기능은 유지됩니다.
검증: 모의 모델로 묶음별 전체 기록 검토, 잘못된 원본/근거 참조 거부, 빈 결과, 제외 상태, DB 이력, HTTP, DOM 카드 표시·원본 미디어 연결.
실제 로컬 모델의 선정 품질과 처리 시간은 사용 환경에서 확인해야 합니다.


### 로컬 LLM 시간 초과 조정

LLM 요청당 대기 시간을 기본 600초로 설정했습니다. Windows HTTP/WSL PowerShell 전달 요청 모두 같은 제한을 사용합니다.
환경변수 K9_OLLAMA_TIMEOUT으로 60~3600초 범위에서 바꿀 수 있습니다.
Qwen3 계열은 API의 think=false를 지정하고 이유를 짧게 생성합니다. 전체 선정 작업은 여러 요청으로 구성될 수 있습니다.
화면에는 경과 시간을 표시합니다. 실제 처리 속도 향상을 보장하지 않으며, 계속 느리면 현재 순찰·최대 3개를 선택하거나 Windows Ollama 모델 상태를 확인하세요.


### 선정 기준: 관측 시각·발화·사람·자세

선정 입력은 녹음 시작/관측 시각, STT 발화 원문, 사람 등장·탐지 기록, 규칙 기반 자세 후보입니다.
제목·메모·태그는 기록 관리에는 유지하지만 이 버전의 LLM 선정 입력에는 포함하지 않습니다.
카드에는 이 네 가지 관측 정보와 선택 이유를 나란히 표시합니다. 녹음 시각이 있으면 DB 저장 완료 시각 대신 녹음 시작 시각을 사용합니다.
STT 원문은 재작성하거나 교정하지 않습니다. 예를 들어 '눈 와주세요'는 그대로 표시하며 원본 음성에서 확인합니다.
발화가 도움 요청으로 읽힌다는 이유나 누워 있음 후보가 있다는 이유는 검토 제안이며 실제 위급 상태 확정이 아닙니다.
사람 탐지 수가 없고 등장 태그만 있는 과거 기록은 수 미확인으로 표시합니다. 같은 시각의 음성과 사람을 같은 발화자로 연결하지 않습니다.
긴 입력의 발췌 제한은 유지하며 카드에서는 전체 발화 원문을 확인할 수 있습니다. 이전 선정 이력은 생성 당시의 기준을 유지하므로 새 기준을 적용하려면 다시 선정하세요.
